<< Chapter 7 | User Input & Output >>

So far, our programs have just talked at people — printing messages and running quietly in the background like a toaster with commitment issues. In this chapter, that changes. We're going to teach our programs to listen. You'll learn how to ask the user a question, grab whatever they type on the keyboard, store it, and use it to decide what happens next.

Example 1 | Getting Input from the Keyboard

  1. Click the button to open this program in a new editor tab.
  2. Then click the Run button or press F9 to run the program.

BASICINPUT.BAS

// Input pauses the program and waits for the user to type something.
// Whatever they type gets stored in the variable you name.

PRINT "What is your name?"
INPUT name$

PRINT "Nice to meet you, "; name$

// Try changing the question and see what happens
// INPUT always waits patiently - it will not move on until you press Enter

Input is how a program pauses and hands control to the user. It waits for keyboard text, and once you press Enter, whatever was typed gets stored in the variable you gave it — just like LET, except the value comes from the person using the program instead of your code.

Example 2 | Asking Multiple Questions

  1. Click the button to open this program in a new editor tab.
  2. Then click the Run button or press F9 to run the program.

ASKQUESTIONS.BAS

// You can ask as many questions as you want, one INPUT at a time

PRINT "Let's get to know each other."

PRINT "What is your favorite color?"
INPUT color$

PRINT "What is your favorite number?"
INPUT favnum

PRINT "Cool! Your favorite color is "; color$; " and your favorite number is "; favnum

// Notice favnum has no dollar sign - it stores a number, not text.
// Input works for both strings and numbers depending on the variable name.

Just like variables, INPUT respects the dollar sign rule — a variable name ending in $ stores text, and one without it stores a number. Chaining several INPUT statements together lets you build simple forms, one question at a time.

Example 3 | Using Input to Shape Output

  1. Click the button to open this program in a new editor tab.
  2. Then click the Run button or press F9 to run the program.

ORDERFORM.BAS

// This is what a real program does - use input to change what happens next

PRINT "Welcome to the drink stand!"
PRINT "What would you like to order?"
INPUT drink$

PRINT "How many would you like?"
INPUT qty

PRINT "Coming right up: "; qty; " "; drink$; "(s)!"

// This is the same idea behind every online order form,
// every login screen, and every search bar you've ever used

This is where input starts to feel like a real program. The output isn't fixed anymore — it changes based on what the player typed. This same pattern, ask a question and respond to the answer, is the backbone of forms, search bars, and login screens everywhere, whether they're built with text input like this or with buttons and menus in a graphical interface.

Example 4 | Putting It All Together: A Simple Chat Game

  1. Click the button to open this program in a new editor tab.
  2. Then click the Run button or press F9 to run the program.

CHATGAME.BAS

// A simple chat game - the computer "talks" back based on what you type

PRINT "Hi there! I'm YoBASIC. What's your name?"
INPUT name$

PRINT "Nice to meet you, "; name$; "! How are you feeling today?"
INPUT mood$

PRINT "Ah, "; mood$; "? Good to know."

PRINT "What's your favorite hobby, "; name$; "?"
INPUT hobby$

PRINT "No way! "; hobby$; " sounds awesome."
PRINT "Thanks for chatting with me, "; name$; ". See you next time!"

// This is a "chat game" because the program reacts to whatever
// the player types - even though the responses are simple, it feels alive
// Try adding your own questions and responses

Congratulations — you just built a chat-style program! It's simple, but this exact pattern (ask, listen, respond) is the foundation of every chatbot, virtual assistant, and interactive character you've ever talked to. Every extra question you add makes the conversation feel a little more alive.
