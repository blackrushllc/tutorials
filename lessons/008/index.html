<< Chapter 8 | Conditional Logic >>

Conditional logic is how a program decides what to do next, kind of like choosing whether to go left, go right, open the mysterious door, or absolutely not open the mysterious door because that is how horror movies start. In this chapter, we'll focus on IF, ELSE IF, and ELSE statements, which let your code respond differently depending on what's happening. We'll also briefly touch on other decision-making tools like switches and loops.

Example 1 | IF Statements

  1. Click the button to open this program in a new editor tab.
  2. Then click the Run button or press F9 to run the program.

BASICIF.BAS

// IF runs a block of code only when a condition is true
// If the condition is false, the code inside is simply skipped

LET age = 20

IF age >= 18 THEN
    PRINT "You are an adult."
END IF

// Try changing age to a number below 18 and run it again
// Notice that nothing prints - the condition was false

IF is the simplest decision a program can make: check something, and if it's true, run the code inside. If it's false, that code just gets skipped entirely, and the program moves on like nothing happened.

Example 2 | ELSE and ELSE IF

  1. Click the button to open this program in a new editor tab.
  2. Then click the Run button or press F9 to run the program.

GRADECHECK.BAS

// ELSE IF lets you check multiple conditions in order
// ELSE catches anything that didn't match a condition above it

LET score = 82

IF score >= 90 THEN
    PRINT "Grade: A"
ELSE IF score >= 80 THEN
    PRINT "Grade: B"
ELSE IF score >= 70 THEN
    PRINT "Grade: C"
ELSE IF score >= 60 THEN
    PRINT "Grade: D"    
ELSE
    PRINT "Grade: F"
END IF

// Only ONE branch runs - as soon as a condition matches, the rest are skipped
// Try changing score to see different grades

ELSE IF chains let you check several conditions in order, and ELSE is your safety net for anything that didn't match. Only one branch ever runs — the moment a condition is true, the program takes that path and skips the rest.

Example 3 | Comparing Values

  1. Click the button to open this program in a new editor tab.
  2. Then click the Run button or press F9 to run the program.

LOGINCHECK.BAS

// Comparison operators: = equal, <> not equal, > greater, < less, >= , <=
// You can combine IF with INPUT to check what the user typed

PRINT "Enter the secret password:"
INPUT password$

IF password$ = "YoBASIC" THEN
    PRINT "Access granted!"
ELSE
    PRINT "Access denied."
END IF

// This same pattern is used behind every login screen you've ever seen
// Try typing the wrong password to see the ELSE branch run

Comparison operators let you check more than just true/false switches — you can compare numbers, or check whether text typed by the user matches exactly. This is the exact logic behind login screens, password checks, and form validation.

Example 4 | Putting It All Together: A Text Adventure Game

  1. Click the button to open this program in a new editor tab.
  2. Then click the Run button or press F9 to run the program.

ADVENTURE.BAS

// A simple text adventure - the player's choice decides what happens next

PRINT "You are standing in a dark hallway."
PRINT "There is a path to the left, a path to the right, and a mysterious door."
PRINT "Choose your destiny. (LEFT, RIGHT, DOOR)"
INPUT choice$

IF choice$ = "LEFT" THEN
    PRINT "You find a small chest with a shiny treasure inside. You win!"
ELSE IF choice$ = "RIGHT" THEN
    PRINT "You walk into a dead end. Nothing happens. You go back."
ELSE IF choice$ = "DOOR" THEN
    PRINT "You open the mysterious door. A monster was awaiting your arrival and lunges out. There is no escape. You get swallowed by the monster!"
ELSE
    PRINT "You stand there confused and the moment passes you by."
END IF

// This is a real text adventure game - built entirely with INPUT and IF
// Try adding more choices, more paths, or even more monsters

You just built a real text adventure game! Every classic choose-your-own-path game, from the earliest computer games to modern branching dialogue in video games, is built on this exact idea: ask the player what they want to do, then use conditional logic to decide what happens next.
